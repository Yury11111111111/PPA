# Builder: домик для хомяка

Пример собираем домики хомяков Плюши и Бублика. Обе версии программы создают одинаковые
комплектации домиков и выводят одинаковый результат.

## До: without_builder.cpp

Конструктор принимает девять аргументов:

```cpp
HamsterHome("Домик Плюши", 100, 50, 20, 28,
            true, false, {"Деревянный домик"}, {});
```

Соседние числа и `bool` трудно различить без объявления конструктора.
Для необязательных тоннелей приходится передавать пустой вектор.
Для постепенной сборки клиенту нужны отдельные переменные со всеми параметрами.
Версия «до» тоже проверяет корректность: валидация возможна и без паттерна.

## После: with_builder.cpp

- **Product — HamsterHome:** готовый домик с закрытыми полями.
- **Builder — HamsterHomeBuilder:** хранит промежуточную сборку и выполняет именованные шаги.
- **Client — main():** выбирает оборудование и последовательность шагов сборки.

Используется Builder без отдельного Director. Клиент собирает каждый домик
через цепочку именованных методов, например:

```cpp
const HamsterHome home = HamsterHomeBuilder("Домик Крошки", 100, 50)
    .add_bedding(20)
    .add_wheel(28)
    .add_water_bottle()
    .add_hideout("Керамический домик")
    .add_tunnel("Пробковый тоннель")
    .build();
```

Каждый шаг возвращает `*this` для цепочки вызовов. Укрытия и тоннели можно
добавлять многократно, в цикле или по условию. Подстилка и колесо устанавливаются
в одном экземпляре: повторный вызов заменяет значение.

`build()` проверяет наличие имени, положительных размеров, подстилки, колеса,
воды и хотя бы одного укрытия, а также совместимость колеса с основанием.
Пустые названия укрытий и тоннелей отклоняются при добавлении.
Обе версии проверяют одинаковые ограничения.

Незавершенный домик закрыт внутри Builder. `build()` возвращает независимую
копию: последующие изменения строителя не меняют готовый результат.
Director не нужен: каждая комплектация задается один раз в `main()`,
поэтому отдельный класс для хранения рецептов только усложнил бы пример.
Пошаговая сборка и проверка результата остаются обязанностями Builder.
Абстрактный интерфейс не добавлен, поскольку реализация строителя одна.

## Почему паттерн полезен

Объект содержит обязательные, необязательные и повторяемые части.
Builder позволяет постепенно накапливать их и выдает готовый результат после проверки.
Именованные методы делают выбор оборудования понятным без просмотра конструктора,
а необязательные части можно просто не добавлять.
Для двух-трех независимых полей было бы достаточно обычного конструктора.
